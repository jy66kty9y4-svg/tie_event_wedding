# Cabinet follow-up: menus, role access and contracts

Subsequent user-approved automation is now implemented locally: standard fields connect to the in-app calendar automatically, and users cells use the anchored multiple dropdown. The future-mapping proposal and native users-control statements below describe this earlier stage; see [[automatic-timing-1011|Automatic timing to the in-app calendar]] for the current behavior.

The latest 15 browser comments were implemented and verified locally, then published with automatic timing as `tie-review-20261011-r2` after the user's explicit request. See [[cabinet-followup-release-1011|Publication and production evidence]]. The implementation/validation details below describe the local stage.

`Select.jsx`/`select.css` draws options inside the document, anchored to the field and bounded by the viewport. Table section/type controls, typed sheet select/file/relation cells and verification dialogs use it; users multi-select remains native. Native fields retain form values/required validation. Keyboard arrows, Home/End, typing, Enter, Tab, outside dismissal and Escape are supported; Escape dismisses the list before the enclosing modal. Desktop avatar opens an account menu with Profile/calendar and Logout; mobile retains its all-controls drawer.

More's wedding website card and direct private website route require the existing strict `project.personalInvitationsEnabled === true` admin invitation switch. This UI gate does not unpublish existing public microsites. All Tables' section/table edit/delete controls use pencil/trash icons and accessible labels. Removed the redundant top Add Row control; the attached draft row and in-table Add remain. Guest Actions defaults to 160 px, stays on one line, and uses virtual column `@guest-actions` in persisted `sheetLayout.columnWidths`; only the guest table accepts that key, with existing 80–800 bounds and edit/structure authorization.

Couple vendor search describes and searches wedding proposals only; agency catalog results require existing global read/catalog permission. Venue has only its title and venue choices, without the booking verification panel. Vendors uses Confirm; evidence offers no file, upload a contract, and existing wedding documents when present. Upload uses the existing private wedding file endpoint and saves `documentStatus: signed`; its returned ID is linked by the existing versioned `selection.booking` command. It immediately appears under Documents/Signed. Failed confirmation after a successful upload retains the uploaded ID for retry. Upload does not imply independent contract verification; that workflow remains in Documents. Cross-wedding file links remain forbidden.

Team timing is available to organizers only. Couple/contractor team URLs normalize to their allowed view; tabs/dock entries and the Team audience choice are hidden. Shared row authorization excludes Team rows in ordinary/offline snapshots, calendar, notifications, direct edits/deletes/restores and dimensions/order metadata. Creating/moving a row into Team is also forbidden. History excludes Team versions even for a custom non-organizer role with history access, and non-organizers cannot change the timing table's key to bypass its boundary. Pair/common calendar links now point to the pair timing route. Generic timing table routes and older cached snapshots receive the same pair filter in the UI. Scoped organizer grants are accepted by backend authorization; normal organizer UI uses its existing global projects grant.

Removed the calendar/responsibility mapping disclosure for everyone. The underlying `timing.configure` API and saved mappings remain. The old control explained which columns are event title/start/end/day offsets/required flag/assigned members; plain-text Responsible is not a staff assignment. Proposed future organizer UX: a Calendar Fields subsection inside column settings, automatic standard mappings, optional staff/day fields and a preview of resulting calendar events. This proposal was explained but not implemented without a new request.

Validation: fresh Vite production build (96 modules), 230/230 Node tests. `cabinet-review.test.mjs` covers team privacy/history/direct command bypasses, guest virtual width persistence/schema edits/bounds, and wedding contract upload/link/read/cross-wedding rejection. CUA on fictional loopback data at 6190 verified desktop account menu without navigation, section popup geometry/save/Escape, draft audience keyboard selection with no Team, retained in-table Add, guest width 160→168 and reload, couple agency search exclusion, Venue without verification, contract upload/confirmation and Documents/Signed after another login, admin switch off/on and couple website card, actual organizer Team rows and removed mapping disclosure. Contract popup stays attached at 390×844 and 2560×1440. Viewport was reset; no browser console errors in checked views. No production writes, deployment, browser download/export, or cold offline startup in this round.
