# Calendar deletion without a frozen interface, 2026-10-11

User requested Calendar in primary wedding navigation, event deletion without a broken interface, automatic list refresh and preservation of other page data. Calendar was already primary in the shared navigation from wedding-card-r1; no new navigation changes were needed.

Reproduced the critical UI failure with a fictional local task opened from Calendar. Task editor and nested delete confirmation closed together, but each old Modal independently restored its captured shell inert/body overflow. Cleanup left the application inert with overflow hidden; clicking Calendar failed until reload. src/ui/modal-lock.mjs now owns a shared, counted, idempotent background lock. Only the last dialog restores the state captured before the first dialog, regardless of close order. Modal delegates to this helper; focus/discard behavior otherwise remains unchanged.

Meeting deletion in src/v2/calendar/Workspace.jsx now uses an in-site confirmation within the existing dialog, catches errors, prevents duplicate deletion, respects the exact calendar delete permission and disables deletion offline. New unsaved meetings are labelled New and expose no Delete. Cancel returns to the same editor. Opening a meeting closes its day chooser, catches fetch failures and ignores obsolete responses. Successful deletion removes only that meeting projection immediately, closes dialogs, refreshes events and shows a success status. A failed refresh retains the other events. useV2Data orders reads to stop older polling from overwriting a newer response or mutation; transient failures retain data, while authorization failures clear it.
