# tie.event

Локальное приложение свадебного агентства: публичный сайт, личные аккаунты, заявки, совместные проекты пары и команды, гибкие таблицы, подрядчики, финансовый учёт и подготовка к работе без сети.

Разработано в отдельной папке. Исходники, базы, домены и действующие сервисы ГУТВ и Finance не изменяются. Анализ реального Excel использован для структуры рабочего процесса; личные данные не импортированы.

## Требования

- Node.js 22.13 или новее с `node:sqlite`; проверено на Node.js 24.19.
- pnpm для установки точных версий из `pnpm-lock.yaml`.
- React 19 и Vite 8, зависимости перечислены в `package.json`.
- Современный браузер с IndexedDB и service worker.

## Обычный локальный запуск

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

При первом запуске используется чистая собственная база. В браузере создайте агентство и основной административный аккаунт. Общего пароля по умолчанию нет.

В текущем рабочем окружении доступен Node из комплектного runtime. `./scripts/start.sh` запускает приложение из любой папки. Все зависимости установлены отдельно для tie.event; React, Vite и Sharp зафиксированы в lockfile. При переносе выполните `pnpm install --frozen-lockfile` в новой копии.

Рабочий адрес: [localhost:4173](http://localhost:4173). Первая настройка создаёт ваше агентство и администратора.

Для знакомства с вымышленными данными есть отдельная демоверсия: [localhost:4174](http://localhost:4174). Учётные записи находятся в локальном `data/demo-credentials.txt`; файл исключён из Git и доступен только владельцу. Демо создаётся командой `npm run demo`, его база — `data/demo.sqlite`. Рабочая база — `data/tie.sqlite`.

Для повторного запуска демо:

```sh
PORT=4174 TIE_DB_PATH=data/demo.sqlite ./scripts/start.sh
```

## Возможности V2

- План подготовки: задачи, зависимости, комментарии, шаблоны и предпросмотр переноса даты.
- Согласования пары: версии вариантов, голоса, применение утверждённой цены к смете без создания платежа.
- Сайт свадьбы: черновик, три шаблона, публикация отдельного снимка и подготовка публичных изображений.
- Семейные RSVP-ссылки, ответы существующих гостей, единая рассадка в таблице и на схеме, экспорт и печать.
- Календарь задач, встреч и оплат с часовыми поясами; проверка занятости участников.
- Внутренние уведомления и восемь проверок готовности с персональным откладыванием.
- Редактор сайта агентства, кейсов, пакетов и FAQ с отдельными черновиками и публикациями.

Новые чувствительные команды требуют сети и не попадают в офлайн-очередь. Чистая установка остаётся без вымышленных проектов и финансов. Для публичного sitemap нужно явно указать домен; внешняя почтовая доставка не подключена и не помечается отправленной.

## Данные

База рабочего приложения и демонстрационные данные разделены. Примеры не должны добавляться в рабочую базу автоматически. SQLite использует WAL; для переноса работающей базы нужен согласованный SQLite backup либо остановка приложения перед копированием базы вместе с её WAL-файлами. Не подменяйте файлы работающей базы.

## Принятые границы

- Бренд, тексты и портфолио временные и заменяются через настройки.
- Окончательный домен и способ размещения не выбраны. В этой задаче приложение запускается локально.
- Приглашения создаются как ограниченные по сроку ссылки для самостоятельной передачи. Почтовая интеграция не настраивалась.
- Без интернета устройство не может мгновенно получить отзыв прав. Сервер заново проверяет их при синхронизации. Неудачные правки требуют явного решения пользователя.
- Настройки нескольких агентств заложены в данные и проверяются тестами; подписки и биллинг не входят в задачу.

## Проверки

`pnpm test` запускает серверные, HTTP и интеграционные проверки, включая миграцию реальных V1-копий, ограничения доступа, гостевые ссылки, конкурирующие изменения и очередь уведомлений. `pnpm build` собирает основной кабинет и отдельный гостевой клиент.

Браузерные проверки выполняются на отдельных временных базах и профилях:

```sh
npm run test:browser
npm run test:ui
npm run test:management
npm run test:offline-ui
npm run test:v2-browser
npm run test:v2-entry
```

Для этих команд нужен Playwright и установленный Chrome. Можно указать `PLAYWRIGHT_MODULE_PATH` и `CHROME_PATH`; в текущем окружении используется комплектный Playwright и Chrome. Покрытие V1 — в `docs/ACCEPTANCE.md`, V2 и карта AC-01–47 — в `docs/v2/VALIDATION-NOTES.md`. Браузерные артефакты сохраняются в `test-results/`.

Офлайн-снимок действует семь дней. Подготовьте проект на каждом нужном устройстве. Выплаты доступны отдельно от полной сметы; таблицы включаются в офлайн по отдельности. Скачивание вложений требует сети, даже если список файлов подготовлен. Ошибки синхронизации сохраняются в очереди и показывают сравнение правки с текущими данными. Выход очищает локальные приватные данные вместе с несинхронизированными правками.
