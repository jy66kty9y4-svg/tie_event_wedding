# Проверки TIE

Проверено 12 октября 2026 на Node 24.19.0: **648/648 тестов**, без ошибок и пропусков. Полный запуск с покрытием занимает около 10 секунд. Для воспроизведения используется Node 24, как в Dockerfile; новые зависимости не добавлены.

## Запуск

```sh
pnpm test
pnpm test:unit
pnpm test:coverage
pnpm test:mutations
pnpm build
```

`test:unit` запускает 372 новые быстрые проверки примерно за 1.3 секунды: чистые функции, клиентский транспорт с подменённой сетью и команды на изолированной SQLite. Полный `test` дополнительно запускает существующие проверки сценариев и HTTP. Все 648 проверок нельзя называть исключительно юнит-тестами.

`test:coverage` завершится с ошибкой при падении тестов или покрытии ниже 93% строк, 86% ветвей и 90% функций. Сейчас **93.31% / 86.75% / 90.16%** соответственно. Это покрытие импортированных серверных модулей и JavaScript логики. React-компоненты, верстка, жесты и ещё не импортированные модули в процент не входят. IndexedDB и полный офлайн-сценарий требуют отдельных браузерных проверок; транспорт `src/client.js` теперь проверяется также в Node.

## Проверка эффективности

`test:mutations` копирует код и тесты во временную папку, проверяет исправную копию, затем меняет 16 правил по одному. Все 16 изменений обнаружены утверждениями: копейки, неизвестная сумма, дата, предел суммы, тип поля, проект/поля прав, авторизация повтора, откат, порядок шаблонов, нулевая аренда, дубликаты фото, комиссия, Excel, геометрия и CSRF. Синтаксическая ошибка, сбой импорта или тайм-аут не засчитываются. Рабочие исходники не меняются. Это целевой набор, а не исчерпывающий показатель всех возможных мутаций.

Отчёт: `test-results/unit-coverage/mutations.json`. Проверки не используют рабочую базу, реальные резервные копии или production API.

## Найденные исправления

1. Некорректный месяц/день мог вызывать `RangeError` и HTTP500. Теперь возвращается ошибка проверки HTTP400.
2. Колонки без строкового ID, с типами из прототипа или `null` проходили проверку либо ломали обход смысловых полей. Структура проверяется до обхода; опасные формулы и `null` строки тоже получают управляемую ошибку. HTTP тест проверяет откат и следующую успешную операцию.
3. Promise результата модульной команды превращался в пустой объект до проверки синхронности. Теперь проверяется исходный результат, и транзакция откатывается.
4. Служебное копирование шаблонов в одном такте часов меняло первый шаблон. Последовательные метки сохраняют порядок. Повторная очистка не выполнялась.

Изменения находятся в рабочем каталоге. Публикация и изменение данных действующего сайта в этой задаче не выполнялись.

## Дальнейшее сопровождение

Дополнительного покрытия требуют ошибки внешних календарных провайдеров, ветви публикации, очередь IndexedDB и React взаимодействия. Для браузера есть отдельные `scripts/*ui-test.mjs` и `scripts/offline-ui-test.mjs`.

Новая бизнес-логика должна импортироваться собственным тестом: встроенный Node отчёт не обнаруживает неимпортированные файлы автоматически. Проверяйте результат, инварианты денег/прав/версий и откат ошибки. Не используйте реальные backup-файлы для фикстур и не снижайте пороги ради непокрытого изменения.
