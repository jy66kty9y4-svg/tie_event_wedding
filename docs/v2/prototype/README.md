# Полный кликабельный макет tie

Визуальная версия от 9 сентября 2026. Главный ориентир — исходный макет и выбранные скриншоты WedCRM: тёплый белый фон, розовый акцент, спокойная типографика, боковое меню и вкладки свадьбы.

## Запуск

Распакуйте архив целиком. Откройте `prototype.html` рядом с папкой `prototype/` в браузере. Для просмотра через локальный сервер выполните из папки с HTML:

```sh
python3 -m http.server 8796 --bind 127.0.0.1
```

Затем откройте `http://127.0.0.1:8796/prototype.html#public`. Во время работы в Codex этот сервер уже запущен.

## Как смотреть

Кнопка **«Экраны»** справа снизу открывает полную карту. Переключатель роли показывает навигацию организатора или пары. «Пустой» и «Требует внимания» демонстрируют состояния ключевых рабочих разделов. «↻» возвращает исходный макет.

| Область | Экраны |
|---|---|
| Агентство | Сегодня, свадьбы, заявки, карточка заявки, все задачи, календарь, каталог и карточка подрядчика, финансы агентства, шаблоны, команда, настройки, профиль, редактор сайта |
| Свадьба | Обзор, план и карточка задачи, согласования и варианты, подрядчики, смета, выплаты, гости и карточка гостя, рассадка, день свадьбы, файлы, таблицы, история, участники, настройки, уведомления, дополнительные разделы, папка дня |
| Публичные страницы | Главная, истории, отдельная история, услуги, отдельная услуга, вопросы, заявка, вход, приглашение, подтверждение ответа |

Некоторые маршруты имеют несколько видов: список/доска/календарь задач; воронка/список заявок; месяц/неделя/повестка календаря. Формы, всплывающие окна, редакторы и экраны подтверждения входят в макет дополнительно.

## Сценарии для просмотра

1. **Путь новой пары.** Главная → истории → кейс → услуги → формат организации → заявка → подтверждение. Через «Войти» можно открыть кабинет организатора или пары.
2. **Рабочий день.** Сегодня → пункт, требующий внимания → задача → изменение статуса или комментарий → обратно к плану. Создание задачи открывает форму, сохранение — новую карточку.
3. **Решение пары.** Согласования → оформление церемонии → выбор варианта → утверждение или запрос изменений. Видны палитры, стоимость, история версий и обсуждение.
4. **Гости.** Гости → поиск/фильтр → карточка → редактирование → приглашение → ответ гостя. Ответ можно изменить на экране подтверждения.
5. **Рассадка.** Выберите гостя в правой панели, затем стол на схеме. Откройте свойства стола, добавьте стол или зону, посмотрите печатное представление.
6. **Финансы и команда.** Смета → расход → изменение суммы; выплаты → поступление; команда → участник → доступ. Тестовые изменения отражаются в интерфейсе до перезагрузки.
7. **Материалы.** Ещё → файлы/таблицы/папка дня. Открываются документы, таблицы и оформленные печатные представления.
8. **Редактор сайта.** Публичный сайт → Главная/Кейсы/FAQ/Сайт свадьбы → изменение текста → сохранение → просмотр соответствующей страницы.

## Границы прототипа

Все пары, сотрудники, подрядчики, суммы и тексты кейсов вымышлены. Фотографии — образцы оформления, не портфолио реального агентства. Макет не подключается к приложению, API, базе данных, почте или платёжным сервисам. Ввод не отправляется наружу, изменения живут только до перезагрузки.

Это эталон внешнего вида и переходов. Серверные функции, права, конкурентное редактирование, настоящие файлы, доставка сообщений и сохранение данных должны реализовываться отдельно по REQUIREMENTS.md и TECHNICAL.md.

## Структура

- `core.js`, `ui.css` — оболочка, навигация, общие стили, режимы просмотра, диалоги.
- `agency.js` — агентство, заявки, проекты, подрядчики, календарь и финансы.
- `workflow.js/css` — подготовка и согласования.
- `event.js/css` — гости, рассадка и программа дня.
- `management.js/css` — материалы, команда, настройки и редактор сайта.
- `public.js/css` — публичные страницы и гостевые формы.
- `assets/` — локальные фотографии; интернет для просмотра не нужен.
- `QA.md` — результаты проверки.

При переносе в приложение сверяйте не только цвет кнопок, но и ширину меню, высоту верхней панели, отступы, размеры заголовков, плотность таблиц, форму состояний и поведение на телефоне. Полная дизайн-система описана в `../DESIGN.md`.
